# 데이트코스 추천 기획안

2026-10-29 개정 · 처음 기획은 2026-10-28 (Claude 문서 초안). 이 파일이 최신이고, 실제 규칙은 [동작방식.md](동작방식.md)에 있습니다.

## 한 줄 소개

**지도에서 지역과 분위기를 고르면, 순위가 매겨진 데이트 코스(구경 → 카페 → 식당)를 동선과 함께 보여주고, 그 코스로 내 일정을 짜서 저장하는 웹 서비스**입니다.

- 주소: https://date-course.kimseongmin.co.kr (서비스 이름은 아직 가칭)
- 예: 성수동 + 감성 → 스탈릿성수 → 성수동 카페거리 → 카페 → 식당

**만드는 이유**: 데이트 코스는 장소를 찾고, 동선을 맞추고, 식당·카페를 고르는 일이 겹쳐서 짜기 힘듭니다. 이미 짜인 코스를 순위대로 보여주면 사용자는 **찾는 대신 고르기만** 하면 되고, 고른 코스를 조금만 고쳐 바로 내 일정으로 씁니다.

## 대상 사용자

| 대상 | 주로 찾는 것 | 어울리는 키워드 |
| --- | --- | --- |
| 커플 (일상) | 새로운 장소, 부담 없는 예산 | 활기찬, 3만원 이하 |
| 소개팅 | 대화하기 좋은 곳, 짧은 코스 | 조용, 실내 |
| 기념일 | 분위기 있는 식당, 야경 | 로맨틱, 야경, 7만원 이상 |
| 친목 (친구 모임) | 여럿이 즐길 거리 | 액티비티, 활기찬 |

"누구와"를 고르면 이 키워드를 미리 골라 주는 기능은 아직 만들지 않았습니다(남은 일).

## 사용 흐름

로그인 없이 다섯 단계입니다.

1. **지역 고르기**: "성수동"·"반석역"·"경복궁"·주소로 검색하거나, 지도를 옮기거나, 인기 지역·내 주변을 누릅니다. 검색하면 지도가 바로 그 자리로 갑니다.
2. **키워드 0~3개**: 분위기·활동·실내외·예산에서 고릅니다. 안 골라도 됩니다.
3. **코스 순위**: 왼쪽(휴대폰은 아래)에 순위 카드, 지도에 순위 핀. 코스를 고르면 단계 이름표와 동선이 그려지고, "◀ ▶"로 다음 코스를 넘겨 봅니다.
4. **코스 상세 = 내 일정**: 단계별 장소(사진·주소·전화·고른 이유)와 걷는 시간. 여기서 바로
   - 단계를 근처 다른 가게로 바꾸고, 가고 싶은 곳을 이름으로 찾아 넣고(없으면 네이버 지역 검색, 그래도 없으면 이름·주소로 직접), 빼고, 순서를 바꿉니다.
   - 날짜·출발 시간, 단계마다 머무는 시간(분)을 정하고 예약한 곳은 도착 시간을 고정합니다.
5. **저장**: "💾 저장"하면 같은 브라우저로 다음에 와도 그대로 열리고, "내 저장"에서 다시 봅니다. 방문자 구분은 힐링룸처럼 브라우저마다 만드는 무작위 id(쿠키 `dc_vid`)로 합니다. 다른 기기에서도 보고 싶으면 "내 저장"에서 비밀번호를 정해 코드를 받고, 다른 기기에서 코드 + 비밀번호로 로그인합니다(그 기기에 있던 일정도 합쳐짐).

## 키워드

| 분류 | 키워드 | 고르는 방법 |
| --- | --- | --- |
| 분위기 | 조용, 로맨틱, 활기찬, 감성, 이색적 | 여러 개 |
| 활동 | 산책, 전시·문화, 체험·공방, 쇼핑, 액티비티, 야경, 맛집 투어 | 여러 개 |
| 실내외 | 실내, 야외 | 하나 (안 고르면 상관없음) |
| 예산 (2인) | 3만원 이하, 3~7만원, 7만원 이상 | 하나 (안 고르면 상관없음) |

장소 키워드는 업종·분류·이름으로 자동으로 붙이고, 관리자가 고칩니다. 코스 키워드는 단계 장소의 키워드에서 모읍니다. 예산 구간은 장소 가격 데이터가 없어 업종으로 어림합니다.

## 데이터

| 출처 | 쓰임 | 비고 |

| 소상공인 상가(상권)정보 (공공데이터포털) | 카페·식당·소품샵·놀거리 등 대부분의 장소 | 분기마다 CSV. 무료, 이용 제한 없음 |

| 행정안전부 전국모범음식점표준데이터 (공공데이터포털) | 품질 신호 (모범음식점 표시) | CSV, 주소·이름으로 맞춤 |
| 네이버 클라우드 Maps | 화면 지도(Dynamic Map), 주소 검색(Geocoding) | 무료 이용량 안 (월 600만·300만 건) |
| NAVER API HUB 검색 API | 지역 검색(우리 데이터에 없는 가게), 이미지 검색(사진 없는 곳) | 지역·이미지 합쳐 하루 25,000건·월 775,000건 무료 (2026-10-29 확인) |

**무료로만 운영합니다.** 그래서 쓰지 않는 것:

- **카카오 API**: 2026-07-21 부터 카카오맵 API 무료 쿼터가 계정의 첫 번째 앱에만 주어지고, 그 밖에는 결제 수단 연결이 필요합니다.
- **네이버 Directions(길찾기)·Static Map**: 무료 이용량이 있지만(Directions 5 는 월 6만 건) 코스 수만큼 부르기엔 모자라고 꼭 필요하지 않아 쓰지 않습니다. 걷는 시간은 직선 거리로 어림합니다.
- **리뷰·별점 긁어 오기**: 지도 서비스 약관 위반이라 하지 않습니다.
- 네이버지도 링크는 API 없이 검색 주소(`https://map.naver.com/p/search/{이름}`)로 겁니다.

네이버 콘솔에는 이용 한도를 무료 이용량보다 낮게 걸고, 서버도 Geocoding 은 하루 3,000번, 검색 API(지역·이미지 합쳐)는 하루 20,000번까지만 부릅니다.

## 순위

**큐레이션 + 사용자 반응**에 키워드 일치·동선·출처 일치·지정 업체·가까움을 더한 점수입니다. 전국을 사람이 다 큐레이션할 수 없으므로 큐레이션이 없는 곳은 자동으로 조합한 코스로 채우고, 반응이 쌓일수록 좋은 코스가 위로 올라오게 합니다. 가중치는 운영하며 조정합니다. 계산식은 [동작방식.md 4절](동작방식.md#4-순위)에 있습니다.

## 기술과 운영

| 영역 | 사용 기술 |
| --- | --- |
| 백엔드 | Java 17, Spring Boot 4.1, Spring Data JPA·JdbcClient, 스케줄러(매일 순위 점수) |
| DB | PostgreSQL 16. 힐링룸과 같은 DB·계정, 전용 스키마 `date_course`. 스키마는 수동 마이그레이션(`ddl-auto=validate`) |
| 캐시 | Redis 7. 힐링룸과 같은 계정, 키는 `healing-room:date-course:` 로 시작 |
| 화면 | React 19 + TypeScript + Vite, 네이버 지도 JavaScript API v3 |
| 배포 | `main` 푸시 → GitHub Actions → 힐링룸과 같은 서버(systemd `date-course`, nginx, Let's Encrypt). 실패하면 이전 버전으로 자동 복구 |

화면 빌드 결과를 Spring Boot jar 안에 넣어 서버 하나로 배포합니다. 화면은 우리 API 와 네이버 지도만 부르고, 비밀 키가 필요한 Geocoding·네이버 검색은 서버가 부릅니다(키가 브라우저에 나가지 않고 호출 한도도 서버가 셈). 상가정보·TourAPI 는 수집기가 미리 불러 DB 에 쌓습니다.

| 테이블 | 담는 것 |
| --- | --- |
| `place`, `place_source` | 합친 장소와 출처별 원본 id |
| `place_merge_candidate` | 같은 장소인지 애매한 쌍 (관리자가 판단) |
| `place_badge` | 공공기관 지정 표시 (모범음식점) |
| `keyword`, `place_keyword`, `course_keyword` | 키워드와 장소·코스 연결 |
| `course`, `course_step` | 코스와 단계 (자동/큐레이션, 순위 점수) |
| `saved_plan` | 방문자 id, 코스, 저장한 일정(단계·머무는 시간·고정 도착, 직접 넣은 가게) |
| `place_suggestion` | 이용자가 알려 준 가게 (모으는 중·공개·합침·거절) |
| `plan_account` | 다른 기기에서도 보기 코드·방문자 id·비밀번호 해시 (연락처 없음) |
| `reaction` | 방문자 id, 코스, 저장·좋아요·다녀왔어요 (버튼은 남음) |
