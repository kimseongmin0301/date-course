# 데이트코스 추천

지도에서 지역과 분위기를 고르면, **순위가 매겨진 데이트 코스**(구경 → 카페 → 식당)를 지도 위 동선과 함께 보여주는 웹 서비스입니다.

**https://date-course.kimseongmin.co.kr**

> 예: 성수동 + 감성 → 스탈릿성수 → 성수동 카페거리 → 카페 → 식당 (약 4시간, 걸어서 이동)

- 로그인 없이 바로 씁니다.
- 전국 장소 **920,698곳**(공공데이터 상가정보 + 한국관광공사 TourAPI)을 바탕으로 코스 **11,815개**를 미리 만들어 두었습니다.
- 무료 서비스만 씁니다(네이버 지도 Dynamic Map·Geocoding 무료 이용량 안).

## 할 수 있는 것

| 기능 | 설명 |
|---|---|
| 지역 고르기 | 검색(동네 "성수동"·역 "반석역"·명소 "경복궁"·주소 "강남대로 396"), 지도 옮기기, 인기 지역 15곳, 내 주변 |
| 키워드 | 분위기(조용·로맨틱·활기찬·감성·이색적), 활동(산책·전시·체험·쇼핑·액티비티·야경·맛집 투어), 실내외, 예산 중 3개까지 |
| 코스 순위 | 지도 가운데 반경 안의 코스를 순위대로. 지도에는 순위 핀, 코스를 고르면 단계 이름표와 동선, 지도 위 "◀ 2위 ▶ · 전체 보기"로 넘겨 보기 |
| 코스 상세 | 단계마다 사진·주소·전화·네이버지도 링크, 단계 사이 걷는 시간, 고른 이유 |
| 다른 가게로 바꾸기 | 단계마다 근처 대안 5곳(같은 기준으로 고른 카페·식당·구경거리)을 보고 "이걸로 바꾸기" (이 브라우저에 저장) |
| 내 일정 만들기 | 가고 싶은 곳을 이름으로 찾아 단계 사이에 넣기·빼기·순서 바꾸기, 날짜·출발 시간을 정하면 단계마다 도착·출발 시간과 끝나는 시간, 캘린더(.ics)로 저장 |
| 구석구석 | 관광공사가 소개한 카페(갤러리 카페·바다 앞 카페 등)는 그 카페를 목적지로 한 코스, 명소가 없는 동네는 소품샵·서점·놀거리 중심의 "동네 코스", 그래도 없으면 반경을 넓혀 찾음 |

## 어떻게 추천하나

1. **장소 모으기**: 상가(상권)정보 CSV(카페·식당·소품샵·놀거리)와 TourAPI(관광지·문화시설)를 합치고 같은 장소는 하나로 묶습니다.
2. **키워드 붙이기**: 업종·분류·이름으로 장소마다 키워드를 자동으로 붙입니다(미술관 → 전시·조용·감성).
3. **코스 만들기**: 명소 하나를 중심으로 걸어서 15분 안의 구경거리 → 카페 → 식당을 골라 잇습니다. 분위기가 맞고 체인점이 아닌 곳을 먼저 고릅니다. 명소 코스에 못 들어간 관광공사 소개 카페는 그 카페를 중심으로, 명소가 없는 동네는 소품샵·놀거리를 중심으로 코스를 만듭니다.
4. **순위 매기기**: 동선·출처 일치·사용자 반응으로 코스 점수를 매기고, 검색할 때 고른 키워드와 거리를 더합니다.

자세한 규칙은 [docs/동작방식.md](docs/동작방식.md)에 있습니다.

## 업체는 어떻게 고르나

**맛이나 평판으로 고르지 않습니다.** 지도 서비스의 리뷰·별점은 약관상 가져올 수 없어서, 가진 데이터(업종·위치·출처·이름·공공기관 지정 정보)로 **데이트 코스에 어울릴 가능성이 높은 곳**을 규칙으로 고릅니다.

**후보에 넣는 조건**

- 중심 장소에서 1km 안, 앞 단계에서 직선 700m(걸어서 약 15분) 안
- 상가정보 최신 분기 파일에 있는 가게 (빠지면 폐업으로 보고 뺌)
- 데이트와 상관없는 업종(병원·편의점·PC방·유흥 주점 등)은 처음부터 넣지 않음. 꽃집·문구점·노래방·당구장은 구경거리로 쓰지 않음

**후보 중 고르는 점수** (단계마다 가장 높은 곳 하나)

| 기준 | 점수 | 뜻 |
|---|---|---|
| 모범음식점 (지자체 지정) | +3 | 위생·서비스를 보고 공공기관이 지정한 곳. 리뷰 없이 쓸 수 있는 가장 강한 품질 신호 |
| 중심 장소와 분위기 키워드가 겹침 | 하나당 +2 | 미술관 코스면 "조용·감성" 카페를 먼저 |
| TourAPI 에도 있는 곳 | +2 | 관광공사가 소개하는 곳 |
| 식당 업종 | 파스타·스테이크 +3, 경양식·일식·동남아 +2 … 국밥·분식 −2 | 데이트에 어울리는 업종을 먼저 |
| 체인점 | −3 | 같은 이름이 전국 15곳 넘거나, "투썸플레이스서초"처럼 체인 브랜드 뒤에 지역·지점명이 붙은 곳. 동네 가게를 먼저 |
| 거리 | 250m 마다 −1 | 가까울수록 위 |
| 이미 다른 코스에 들어간 곳 | 넣은 횟수마다 −0.7 | 한 가게가 모든 코스에 나오지 않게 |

코스 상세 화면에는 단계마다 **고른 이유**(✓ 모범음식점, ✓ 관광공사 소개, ✓ 체인 아닌 동네 가게)를 보여줍니다.

**한계와 품질을 올리는 방법**

| 한계 | 대응 |
|---|---|
| 같은 조건의 가게가 여럿이면 맛·분위기와 상관없이 뽑힐 수 있음 | 모범음식점 같은 **공공 지정 정보**로 가산점 (전국 9,616곳 반영, 코스 3,685개에 들어감) |
| 리뷰가 없어 실제 만족도를 모름 | **사용자 반응**(저장·좋아요·다녀왔어요)이 쌓이면 좋은 코스가 위로 (순위 계산에 이미 반영, 버튼은 다음 작업) |
| 이상한 가게가 섞일 수 있음 | **관리자 큐레이션**으로 직접 등록·수정한 코스는 +20 (다음 작업) |
| 상가정보는 분기 갱신이라 최근 폐업이 남을 수 있음 | 분기마다 새 파일을 넣으면 빠진 가게는 폐업 처리. 여러 분기를 거치며 **오래 영업한 가게**에 가산점을 줄 수 있음 (데이터가 쌓이면) |

## 기술

| 영역 | 사용 기술 |
|---|---|
| 백엔드 | Java 17, Spring Boot 4.1 (Web MVC, JPA, JdbcClient), 포트 18290 |
| DB·캐시 | PostgreSQL 16 (전용 스키마 `date_course`), Redis 7 |
| 화면 | React 19, TypeScript, Vite, 네이버 지도 JavaScript API v3 |
| 배포 | GitHub Actions → 서버(systemd, nginx, Let's Encrypt). 화면은 jar 안에 함께 들어갑니다 |

```
backend/    Spring Boot API 서버 + 데이터 수집기 (화면 빌드 결과도 jar 에 넣어 함께 서빙)
frontend/   React 화면
db/         DB 스키마 (사람이 직접 실행하는 마이그레이션)
deploy/     서버 설치·배포 스크립트 (systemd, nginx)
docs/       기획·동작 방식 문서
```

## 로컬 실행

필요한 것: Java 17, Node 22, PostgreSQL·Redis 접속 정보, (선택) 네이버 지도·TourAPI 키

```bash
cd backend
cp .env.example .env   # DB·Redis·키 값 넣기
./gradlew bootRun      # http://localhost:18290
```

```bash
cd frontend
cp .env.example .env   # 네이버 지도 Client ID
npm install
npm run dev            # http://localhost:5173 (/api 는 백엔드로)
```

- 테스트: `cd backend && ./gradlew test -Pci` (DB 없이), 화면은 `npm run build && npm run lint`
- DB 스키마는 앱이 만들지 않습니다. `db/V*.sql` 을 순서대로 직접 실행하세요(`ddl-auto=validate`).

## 데이터 넣기

```bash
cd backend
./gradlew bootRun --args="--collect=sbiz --path=../data/sbiz/202606"   # 상가(상권)정보 CSV (약 5분)
./gradlew bootRun --args="--collect=tour"                              # TourAPI 전국 (약 40분)
```

```bash
./gradlew bootRun --args="--collect=model --path=../data/model"        # 모범음식점 CSV (지정 표시, 1분 안)
```

수집이 끝나면 키워드 → 코스 → 순위 점수까지 저절로 다시 만듭니다. 규칙만 바꿨을 때는 `--collect=keywords`, `--collect=courses`, `--collect=scores` 로 그 단계부터 다시 돌립니다.

상가(상권)정보는 [공공데이터포털](https://www.data.go.kr/data/15083033/fileData.do)에서 분기마다 받아 `data/sbiz/{기준월}/` 에, 모범음식점은 [전국모범음식점표준데이터](https://www.data.go.kr/data/15096282/standard.do)를 받아 `data/model/` 에 둡니다(저장소에는 올리지 않음).

## 배포

`main` 에 푸시하면 GitHub Actions 가 화면 검사·빌드 → 백엔드 테스트·빌드 → 서버 전송·재시작·상태 확인까지 하고, 실패하면 이전 버전으로 되돌립니다. 서버 구성은 [AGENTS.md 9절](AGENTS.md#9-배포)을 보세요.
